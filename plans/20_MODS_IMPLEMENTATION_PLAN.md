## 2. Scope & parity definition

### 2.1 In scope

1. **Discovery / metadata / ordering**
   - Folders, `.zip`, and `.jar` candidates in `modDirectory`; `resolve_root` unwraps a single top-level directory (GitHub zipball shape); meta files `mod.json`, `mod.hjson`, `plugin.json`, `plugin.hjson`.
   - `ModMeta` parity fields: `name`, `internalName` (derived), `displayName`, `author`, `description`, `subtitle`, `version` (first line only), `minGameVersion`, `main`, `java`, `hidden`, `dependencies`, `softDependencies`, `contentOrder`, `texturescale`, `pregenerated`, `iosCompatible`, `legacyCompatible`, `repo`; color stripping and truncation constants (`maxModSubtitleLength = 40`).
   - Dependency resolution with the exact `ModState` semantics and sort order (`enabled, contentErrors, missingDependencies, incompleteDependencies, circularDependencies, unsupported, disabled`), soft dependencies, circular detection, settings-based enable flag, `requiresReload`, `skipModLoading` (`modcrashdisable`), per-mod `failed` flag.
   - `mods/<internal-name>/config.json` config-folder API (`getConfigFolder`/`getConfig`) retained as a path contract for the OD1 script host; JSON-only mods do not call it.
2. **JSON content (`ContentParser` equivalent)** for the top-level kinds Mindustry parses: `block`, `unit`, `weather`, `item`, `liquid`, `status`, `sector`, `planet`, `team`; nested definables inside them (`bullet` objects/arrays, `effect` objects/arrays, `ability`/`drawer`/`part` kind objects, `shoot` patterns), and string references to `unitCommand`/`unitStance`. Both proper and legacy folder names (`weathers`, `status`, …), `contentOrder` first-then-alphabetical per mod, `finishParsing` two-phase binding, JSON `name`/`description` → bundle registration, `<mod>-` name prefixing via 02 `transform_name`, per-content error isolation (`minfo.error`, `ModContentInfo.base_error`, `erroredContent`), unknown-field warnings, null-field validation.
   - `type`/`template`/`controller` resolution through a committed, generated **ClassMap replacement** (`class_tags`), including upstream fully-qualified class-name aliases; no `Class.forName` fallback (impossible without a JVM).
3. **Data patches (`DataPatcher`/`DataManager` parity)**
   - Patch format v2: top-level singular content type → content names → fields; dotted paths; nested object syntax; flat key syntax; array index assignment; `+` append (single and multi), `"-"` map-key removal; `ObjectSet` `+`; `ObjectFloatMap`/`ObjectMap`/`Attributes` edits; `consumes` merge (`readBlockConsumers`); `requiredPlanets` server gating; `@NoPatch` refusal; unknown-field warnings; created-object `init/postInit/load` and `afterPatch` on touched content.
   - Replace-only apply/unapply with recorded `ResetAction`s + registry index restore (02 `RegistryIndexSnapshot`); no stacking between applications; per-mod fresh patcher in `loadModPatches`.
   - `fixContentArrays` growth for `ItemSeq`/`ItemModule`/block content arrays and editor tile references.
   - `patches` region read/write from maps/saves via 04 hooks; `DataManager` used by the editor (plan 19).
4. **Data assets**
   - `DataAssetType::{patch, content, bundle, image, sound, music}` with exact folder names, extensions (`json/hjson/json5`, `properties`, `png`, `mp3/ogg`), embedded flags, and `compareTo` ordering.
   - Per-asset records (`DataAsset` base: `path`, `name`, sha256 `byteHash`/`stringHash`, cache file, embedded read/write, `validPath`), `PatchAsset` (UUID path, parse fallback), `ContentAsset` (type, data, warnings, errored, `loadableContent` restriction), `ImageAsset` (`generated/`), `SoundAsset`, `MusicAsset`, `BundleAsset` cache.
   - `DataAssetCache` — sha256 addressing + custom base32 (52 chars), `data/assetCache/`, `add`/`addOverride`/`get`/`has`.
   - Appliers: `DataImagePacker` (`dp-` region prefix, `net-` runtime prefix, generated prioritization, env-page reservation, atlas append — plan 03), `DataAudioLoader` (`dp-` name prefix, `soundIdOffset = 100_000`, stream threshold 100 000 bytes, logic `@sfx-` vars, unregister on unload), `DataBundleLoader` (locale chain merge, snapshot/restore originals).
   - Application from mod folders, from map/save assets (04 patches region), and from server-delivered blobs (21 interface defined here).
5. **Sprite/asset overrides:** `sprites/` (`<mod>-` prefix with upstream's "already category-prefixed" rule) vs `sprites-override/` (unprefixed + missing-target warning); page routing (`environment`/`rubble`/`ui`/`main`); `texturescale`; `pregenerated` (no bleed, no generated icons); mod icon `icon.png` else `preview.png`.
6. **Mod UI:** `ModsDialog` list/import/enable/disable/delete/details/errors/updates on plan-14 widgets; GitHub mod browser/import (`ModListing`, version matching) with downloads performed by the UI layer; error dialogs for content errors and unmet dependencies; `requiresReload` banner. Steam Workshop publish/view is stubbed for plan 22.
7. **Scripting seam (OD1):** `ScriptHost` trait, `NoScriptHost` shipping default; script mods marked unsupported with a clear message; candidate engines and Java-mod migration policy documented; decision gated at M8.
8. **Server parity:** headless mod loading/discovery/content/patch path (no Godot, no renderer), server data assets, `dp-` audio/image asset records even when not playable, required/soft mod identity list for the 21 join handshake, hidden-mod rules.

### 2.2 Definition of done

A **fixture data mod** (folder and zip) can be dropped into `data/mods/`, discovered, dependency-ordered, parsed into real registry content with correct prefixed names and bundle entries, visual sprite overrides appear in game, its `patches/*.json` edit vanilla content and un-apply cleanly, its map-embedded assets load from a saved map, errors in one file never corrupt other content, and the ModsDialog can install/enable/disable/delete it with correct states — all verified headlessly (`mind-headless mods *`) and in-engine (MCP). `cargo test -p mind-core` covers the ported `PatcherTests`/`DataAssetTests` semantics offline. Script mods are the only documented gap and are surfaced, not ignored.

### 2.4 Deliberate deviations (reason stated)

1. **No JVM: Java class mods, plugins, `ModClassLoader`, `ClassLoaderCloser`, Rhino `Scripts` are not ported** (HIGH_LEVEL_PLAN §9, OD1). `main`/`java` metadata is still parsed and shown; such mods load their JSON/assets, and their code hooks (if any) are marked unsupported. `ModClassLoader`'s "mods must not package Mindustry" check becomes the inverse: a JAR with classes on the classpath is never executed.
2. **`ClassMap.java` (generated Java) → committed `class_tags` manifest + static registry.** Rust has no runtime reflection; only kinds the port implements are resolvable. Unknown type names fail with the upstream-style message. Drift is CI-checked (`mind-tools mods classmap --check`).
3. **Reflection-based field assignment → explicit field setters per kind.** Upstream `Json` reflection over Java fields becomes a `FieldSink` per content kind; the field name vocabulary is preserved 1:1 (`camelCase`), and unknown fields still warn-and-ignore (`ignoreUnknownFields = true`). A parity ledger (`parity/ledgers/mod_fields.md`) tracks coverage.
4. **TextureRegion fields store region names (`RegionName`) in `mind-core`**; binding to `AtlasTexture` happens in `mind-gdext`/plans 03/16 (client only, already true for plan 02 metadata).
5. **`Config`/`Mod.init`/`registerServerCommands` hooks are unavailable** to JSON-only mods; exposed to OD1 script hosts later. Server commands from `plugins` are not available until the script host decision.
6. **Mod browser Steam Workshop paths (`Publishable`, `createSteamFolder`, `steamID` settings) are stubs** owned by plan 22; local/GitHub import is full parity.
7. **`DataImagePacker` server-side generated sprites keep upstream's partial behavior** (upstream TODO: "doesn't actually work on the server yet"); client-side is full parity.
8. **No hot reload.** Enable/disable/delete/import set `requiresReload` exactly like upstream; reload = app restart. Map-embedded data assets remain runtime-reloadable (upstream behavior).
9. **Object graph iteration order** follows the plan-02 rule (insertion-ordered collections, explicit sorts); patch traversal order is JSON key order (serde preserves object order via `indexmap`/`preserve_order`).

### 3.2 `Mods` manager, metadata, discovery, dependency ordering

```rust
pub struct Mods {
    mods: Vec<LoadedMod>,              // all discovered, stable sort (state ordinal, name)
    last_ordered: Option<Vec<ModId>>,  // cache for ordered_mods()
    requires_reload: bool,
    new_imports: Vec<ModId>,
    failed_to_launch: bool,
    script_host: Option<Box<dyn ScriptHost>>,
    error_log: ModErrorLog,
}
pub struct ModId(u16);                       // per-run index into `mods`; never serialized
#[repr(u8)] pub enum ModState { Enabled=0, ContentErrors=1, MissingDependencies=2,
    IncompleteDependencies=3, CircularDependencies=4, Unsupported=5, Disabled=6 }

impl Mods {
    pub fn load(&mut self, fs: &dyn FileSystem, dir: &str, settings: &mut SettingsStore) -> ModLoadReport;
    pub fn ordered_mods(&mut self) -> Vec<ModId>;      // deps.topological, enabled only
    pub fn get_mod(&self, name: &str) -> Option<ModId>; // internal name
    pub fn set_enabled(&mut self, id: ModId, enabled: bool, st: &mut SettingsStore);
    pub fn import_mod(&mut self, path: &str, force_enable: bool, fs: &dyn FileSystem) -> Result<ModId, ModLoadError>;
    pub fn remove_mod(&mut self, id: ModId, fs: &dyn FileSystem) -> Result<(), ModLoadError>;
    pub fn requires_reload(&self) -> bool;
    pub fn skip_mod_loading(&self, st: &SettingsStore) -> bool;
    pub fn fingerprints(&self) -> Vec<ModFingerprint>; // enabled && !hidden
    pub fn get_incompatibility(&self, out: &mut Vec<String>) -> Vec<String>; // port
    pub fn get_mod_strings(&self) -> Vec<String>;      // "name:version"
    pub fn each_enabled(&self, f: impl FnMut(&LoadedMod));
    pub fn has_content_errors(&self) -> bool;
}
```

- **Discovery**: candidates = entries under `modDirectory` with `jar|zip` extension or a directory containing one of the four meta files (after `resolve_root`); `.jar` is treated as a zip container (metadata/content/assets read, code ignored, `java` surfaced). Ordering is filesystem enumeration then `sortMods` (state ordinal, then name).
- **`resolve_root`**: unwrap a single top-level directory; delete `.DS_Store` on macOS paths; zip paths are always translated through `LoadedMod.root`, never `file` (mod/AGENTS.md gotcha).
- **`ModMeta`** (struct fields in §6.2): color-strip `name/displayName/author/description/subtitle`; default `displayName = name`, `version = "0"` and truncate at first `\n`; `internalName = name.to_lowercase().replace(' ', '-')`; `min_major()` parses before the first dot with `0` fallback.
- **Dependencies**: port `resolveDependencies`/`resolve` verbatim (DFS with a `visited` set, `ordered` `IndexSet`, `invalid` `IndexMap`; a dependency is satisfied by another known mod unless its settings-enabled flag is `false`; soft dependencies ignored when missing; cycles → `circularDependencies`). `ordered_mods()` recomputes only enabled mods and caches until invalidated.
- **State resolution** after load: `unsupported` when `!is_supported()` (blacklist list ported, `minGameVersion` major vs `minModGameVersion = 136`; headless is always supported); `disabled` when `!should_be_enabled()` (settings `mod-<name>-enabled`, default true). `failed()` reads `mod-<name>-failed`.
- **`ModSource`** `{ LocalFolder, LocalZip, ImportedZip, BrowserZip(14), Workshop(22) }`; `has_steam_id` is a stub returning `false` in this plan.
- **Config helpers**: `config_folder = modDirectory.join(internal_name)`; `config() = config_folder/config.json`; reserved for `ScriptHost` (OD1) and `plugin`-style runtime config. JSON-only mods have no caller (documented deviation 2.4.5).

### 3.4 JSON content parser (`ContentParser` equivalent)

Trait usage (02 §3.6): `ModsContentProvider` implements `ModContentProvider`; `ContentJsonParser` implements `ContentParserHook`:

```rust
pub struct ContentJsonParser {
    class_tags: &'static ClassTagMap,
    reads: Vec<ReadOp>, post_reads: Vec<ReadOp>,
    current_mod: Option<ModId>, current_content: Option<ContentRef>, current_file: Option<String>,
    warnings: Vec<ModWarning>, listeners: Vec<Box<dyn ParseListener>>,
    allow_class_resolution: bool, allow_asset_loading: bool, allow_patching: bool,
    content_types: HashMap<ClassKind, ContentType>,   // plan 02 class-kind -> type
    to_be_parsed: IndexSet<ContentRef>,
}
impl ContentParserHook for ContentJsonParser {
    fn parse(&mut self, reg: &mut ContentRegistry, asset: &ContentAsset) -> Result<ContentRef, ContentParseError>;
    // + finish_parsing(), mark_error(), check_null_fields(), read_block_consumers()
}
```

- **Entry**: `parse(mod, name, json, file, type)` — strip extra `#` → `\#` for `.json` (upstream quirk); reject non-object; select the type parser; bind or locate existing content (patching allowed only for the mod-content loader, not for `DataPatcher`'s parser).
- **Name prefixing:** every newly created content is constructed with `reg.transform_name(name)` while `reg.set_current_mod(Some(mod))`; names are never passed pre-prefixed to `Mappable::name`.
- **Locate rule:** `locate(type, name)` tries the vanilla name first, then `<mod>-<name>`; if the JSON file's stem matches existing content *and* has no `type`, it patches that content; if it has `type`, it creates new prefixed content and warns (upstream message kept).
- **Two-phase reads:** `parse()` binds and queues a `ReadOp`; `finish_parsing()` drains `reads`/`post_reads`, catches per-op failures into `mark_error`, and clears `current_mod/current_file`. This yields upstream's "content exists but fields apply later" behavior used by patches and cross-references.
- **Per-kind behavior** (port map §4): blocks handle `consumes` via `read_block_consumers`, size limit `max_block_size = 16`, default `buildVisibility = shown` when `requirements` present; units handle `template` (preset kind), `type` (unit entity kind), `controller`/`aiController`, `defaultController`, `requirements` (reconstructor upgrade or factory plan via plan 07/11 registries), and `waves` (SpawnGroups fed to plan 11's `WaveSink`); statuses install `opposite`/`affinity` transition data through plan 02 `TransitionSpec`; sectors require `sector` index, disallow overwriting on non-patch parsing, store `rules` as a serialized `RuleOverrideSpec` (plan 12 applies at runtime); planets create one sector and store mesh/cloud-mesh kind tags + rule override; teams require a `team` tag.
- **Nested resolvers** (`nested/*.rs`): `Effect` (string → plan 17 registry; array → `MultiEffect`; object → `type` kind + fields), `BulletType` (string → internal bullet; array → `MultiBulletType`; object → `<Type>BulletType` class map first, `type` field second), abilities/draw parts/shoot patterns as kind tags + fields, `Sortf`/`Interp`/`Blending`/`CacheLayer`/`Attribute(s)`/`BuildVisibility`/`Schematic` field parsers exactly as upstream `classParsers`.
- **Bundle registration** (`read_bundle`): for `name`/`description`, determine the target key `<type>.<prefixed-or-existing-name>.name|description`, write into the **top-most parent** bundle only if absent, set `localized_name`/`description` on located patch content, then remove the keys before field reading.
- **Error marking:** `mark_error(content, mod, file, err)` sets `minfo.mod/source_file/error/base_error`, adds to `mod.errored_content`, and pushes a `ModError` with the upstream-formatted text (File line, `[accent][[JsonParse][]`, cause chain with `mindustry.`/`arc.` stripped). `handle_content_error` (02 sink) routes lifecycle failures the same way.
- **Null validation:** `check_null_fields` refuses null on non-nullable fields (with the upstream `"Field '@' cannot be null."` warning), except implicit-nullable region fields (`TextureRegion`-equivalent `RegionName`) in headless.

### 3.5 `ClassMap` replacement

- `mind-core::mods::json::classmap` exposes `ClassTagMap` built from the committed `classmap_gen.rs` plus runtime-registered kind factories from plans 02/07/10/11/17 (registration macro `register_kind!(short, full, scope, factory)`).
- Manifest entries: `{ "alias": "GenericCrafter", "scope": "Block", "tag": "block.generic_crafter" }`; both the simple name and the upstream fully-qualified name (`mindustry.world.blocks.production.GenericCrafter`) are aliases.

- `allow_class_resolution = false` (patcher parser) disables only the arbitrary-FQCN fallback (which Rust rejects uniformly with the upstream `noResolution` warning); `ClassMap`-style aliases remain resolvable — required by `PatcherTests` (`LaserBulletType`, `ShootAlternate`, `DrawRegion`).

### 3.6 Data patches (`DataPatcher`)

```rust
pub struct DataPatcher {
    applied: bool,
    snapshot: Option<RegistryIndexSnapshot>,
    resetters: Vec<ResetAction>,
    after: Vec<Box<dyn FnOnce(&mut ContentRegistry)>>,
    used: IndexSet<PatchTarget>,               // ContentRef | field records
    visit_stack: Vec<VisitRef>,
    added_content: Vec<ContentRef>,
    added_logic_vars: Vec<LVar>,
}
impl PatchHook for DataPatcher { fn apply(&mut self, reg, patches: &[PatchAsset], content: &[ContentAsset]) -> Result<Vec<ResetAction>, ContentError>; }
impl DataPatcher {
    pub fn unapply(&mut self, reg: &mut ContentRegistry, reload_world: bool);
    pub fn load_mod_patches(mods: &Mods, reg: &mut ContentRegistry, fs: &dyn FileSystem);
}
```

- **Apply** is replace-only: if `applied` → `unapply()` first; snapshot the registry index (02) and record attribute-table resets; apply `ContentAsset`s first (restricted parser: `allow_class_resolution=false`, `allow_asset_loading=false`, `allow_patching=false`; `dpMod` identity; `loadableContent` filter; `fixContentArrays` when item/liquid/block added), then `PatchAsset`s in list order, then after-callbacks.
- **Patch traversal** ports `assign()`: root object → singular type name → content name (or the flat `block.name.field` key sugar) → dotted path descent (records resetters for intermediate objects/array indices) → final leaf. Handled targets: `Seq`/array (`+`, numeric index, whole-array assignment), `ObjectSet` (`+`), `ObjectMap`/`ObjectFloatMap` (`key: value`, `key: "-"` removal, key conversion by metadata key type), `Attributes`, block `consumes` (merge/replace with `remove:` entries; reset captures consumer builder, `hasItems/hasLiquids/hasPower/acceptsItems`), `UnitType.controller/aiController/type`, general fields through the 02 field table with `PATCH_DENIED` refusal (`@NoPatch`).
- **`modified_field`** records a reset action keyed by `(object identity, field, previous value)` once (so repeated edits in one apply don't stack resets). Array/`Seq` element resets are recorded positionally.
- **`created` callback:** when `assign_value` instantiates a `Weapon`/content/ability/draw part/bullet, invoke the parser listener so the object runs `init()/post_init()` and (client) `load()`; parent lookup walks the visit stack exactly like upstream.
- **`visit` + `after_patch`:** touched `Content` runs `after_patch()` (plan 02) once; `created` sets `needs_array_fix` for item/liquid/block additions.
- **`unapply`:** `call_content_remove()` for `dpMod` content (`remove_content`), swap back the index snapshot, run resetters in **reverse** order, remove added logic vars, clear state, then `fix_content_arrays`.
- **`requiredPlanets`:** removed before traversal; when `Vars.headless` and the active rules planet is not in the list, the whole `PatchAsset` is skipped (upstream only skips when `state.rules.planet != null`).
- **Per-mod patches:** `load_mod_patches()` iterates `ordered_mods()`; each mod with `patches/` gets its own `DataPatcher` (so mods never reset each other) with files sorted; failures log `Failed to apply patches from mod <name>` and mark the asset `error` + warnings.

### 3.14 Invariants

1. Mod identity travels by **name/version strings only**; `ModId`/content IDs never appear in saves or network data (02 §3.2).
2. `DataAssetCache` is content-addressed: bytes for a hash never change; a new asset = new hash + new cache file. Cache writes are atomic.
3. Patch application is **replace-only**; `unapply` restores via `ResetAction`s + index snapshot in reverse order; double-apply never stacks.
4. Unknown JSON fields warn, never fatal; structural errors mark content errored and remove only that content (error isolation).
5. `dp-`/`net-` region and audio prefixes are reserved; mod-authored names never start with them.
6. `mind-core::mods` contains no Godot/tokio types; image/audio/atlas side effects happen through events/hooks in `mind-gdext`/plans 03/18 (CI dependency check).
7. Mod content is appended after vanilla; registration order in `mind-core` reproduces upstream run order (contentOrder → file name ordering within mod; mod order = `ordered_mods`).
8. Every ported file carries the GPL header; generated `classmap_gen.rs` carries `// GENERATED — do not edit`.
9. `requiresReload` is set on enable/disable/delete/import of non-disabled mods; runtime data assets from maps/saves remain reloadable.
10. Fixture mods are committed under `parity/mod_fixtures/` with expected dumps; CI diffs them (23).

## 6. Data & formats

### 6.1 Mod directory & package layout

```
<data>/mods/<file>.zip | <file>.jar | <folder>/
  mod.json | mod.hjson | plugin.json | plugin.hjson   (first found; required)
  icon.png | preview.png
  content/<folder>/<name>.{json,hjson}                (folder = ContentType::folder or legacy plural)
  patches/<name>.{json,hjson}
  sprites/**.png
  sprites-override/**.png
  bundles/bundle[_<locale>].properties
  sounds/**.{ogg,mp3}
  music/**.{ogg,mp3}
  scripts/main.js                                     (unsupported by default; OD1)
  config.json                                         (reserved for ScriptHost)
<data>/assetCache/<52-char-base32>                    (sha256-addressed blobs)
<data>/assets/sprites/generated/<hash>/<name>.png     (server-generated content sprites)
```

`resolve_root` unwraps a single top-level directory inside folders/zips (GitHub zipballs). All content paths resolve through `LoadedMod.root` (zip-aware), never the outer file.

### 6.2 `mod.json` / `mod.hjson` (all fields optional except `name`)

```json
{
  "name": "Test Mod",
  "displayName": "Test Mod",
  "author": "tester",
  "description": "Fixture mod",
  "subtitle": "fixture",
  "version": "1.0",
  "minGameVersion": "146",
  "main": null,
  "java": false,
  "hidden": false,
  "dependencies": ["lib-mod"],
  "softDependencies": ["extra-mod"],
  "contentOrder": ["base-item", "derived-block"],
  "texturescale": 1.0,
  "pregenerated": false,
  "iosCompatible": true,
  "legacyCompatible": false,
  "repo": "owner/repo"
}
```

Defaults: `minGameVersion "0"`, `version "0"` (first line), `displayName = name`, `texturescale = 1.0`, empty dep lists/`contentOrder`; `dependencies`/`softDependencies` are internal names (lowercase/hyphenated). Blacklist entries ported from `Mods.blacklistedMods` (name and name:version forms).

### 6.3 Content JSON (examples; field names are upstream camelCase)

```json
// content/items/test-ingot.json  -> name "testmod-test-ingot"
{ "name": "Test Ingot", "description": "…", "hardness": 3, "cost": 1.5 }

// content/units/test-mech.json
{
  "type": "mech", "template": "MechUnitType",
  "name": "Test Mech", "health": 500, "speed": 0.6,
  "weapons": [ { "mirror": true, "reload": 30,
    "bullet": { "type": "LaserBulletType", "damage": 10, "length": 120 } } ],
  "requirements": { "block": "testmod-test-factory", "time": 60 }
}

// content/blocks/test-smelter.json
{
  "type": "GenericCrafter", "size": 2, "health": 200,
  "requirements": ["testmod-test-ingot/20"],
  "consumes": { "items": ["testmod-test-ingot/1"], "power": 0.5 },
  "outputItems": ["testmod-test-ingot/1"]
}
```

Name generation: `<internal-name>-<file-stem>`; `name` keys become root-bundle `<type>.<prefixed-name>.name` and are removed before field reading. A file whose stem matches vanilla content and has no `type` patches it in place (mod-content loader only). Bullets/effects/abilities/commands/stances are only definable nested; `unitCommand`/`unitStance` strings resolve against registries.

### 6.4 Patch format v2 (`DataPatcher.patchFormatVersion = 2`)

```json
{
  "name": "optional label",
  "requiredPlanets": ["serpulo"],
  "block.ground-factory.plans": { "unit": "flare", "requirements": ["surge-alloy/10"], "time": 100 },
  "unit.dagger.weapons.+": { "name": "navanax-weapon", "bullet": { "type": "LightningBulletType", "lightningLength": 999 } },
  "block.fuse.ammoTypes": { "titanium": "-", "surge-alloy": { "type": "LaserBulletType", "damage": 100 } },
  "block.conveyor.consumes": { "remove": "items", "power": 1 },
  "block.grass.attributes.oil": 99
}
```

Accepted top-level forms (all upstream): flat dotted keys; `block: { name: { field: … } }`; `{ "block.name": { … } }`; `{ "block.name.field": value }`; index paths (`upgrades.0.1`, `weapons.0.bullet.damage`); `+` appends single or arrays; `"-"` removes an `ObjectMap` key; `consumes` merges with `remove: <type|all>` and typed entries (`item`, `items`, `liquid`, `liquids`, `power`, `powerBuffered`, `coolant`, boost variants). Unknown fields/values warn and continue; `@NoPatch` fields refuse with `"Field '@' cannot be edited."`.

### 6.5 Data asset records & binary codec (patches region, owned by 04)

Per-asset codec (inside 04's `patches` region, `u32 version = 2` → `i32 count`):

```
u8  type ordinal (DataAssetType)
utf8 path
bool embedded
embedded: u32 len + bytes (Patch/Content write their UTF-8 payload; Bundle/Image/Sound/Music write cache-file bytes)
external: 32-byte sha256
```

`ContentAsset` additionally stores its `ContentType` ordinal (`u16`) in the payload. `PatchAsset` stores the patch text; `BundleAsset` payload is the `.properties` text. Missing external cache files log a warning and stay unresolved (`get_missing_assets`).

### 6.6 `DataAssetCache` addressing

`name = base32(sha256(bytes))`, alphabet `ABCDEFGHIJKLMNOPQRSTUVWXYZ234567`, exactly 52 chars, no padding (port of `DataAssetCache.encodeHash`; unit-tested against known vectors). File `<data>/assetCache/<name>`. `add` writes only when the existing file length differs; `add_override` maps a hash to a server-generated path; `get(byte[32])`.

### 6.7 ClassMap replacement manifest

`parity/mod_classmap.json` → generated `classmap_gen.rs`:

```json
{ "classes": [
  { "alias": "GenericCrafter", "scope": "Block", "tag": "block.generic_crafter" },
  { "alias": "mindustry.world.blocks.production.GenericCrafter", "scope": "Block", "tag": "block.generic_crafter" },
  { "alias": "LaserBulletType", "scope": "BulletType", "tag": "bullet.laser" },
  { "alias": "ShootAlternate", "scope": "ShootPattern", "tag": "shoot.alternate" }
] }
```

`mind-tools mods classmap [--check]` regenerates from the kind manifests; CI fails on drift. Runtime registration (`register_kind!`) lets plans 07/10/11/17 add tags without editing the generated file.

### 6.8 Save `patches` region (04 interface)

`04`'s `read_data_patches`/`write_data_patches` call `GameState::data` (`Box<dyn DataAssets>`): read → decode records → `DataAssets::load`; write → `all_assets()` → per-asset codec above; `force_embed` when `SaveOptions.embed_assets`; `hasExternalAssets` meta tag from `all_external_assets`. `patchFormatVersion` mismatch on read → upstream-style error (04 owns message). `MapIO::write_map(embed_assets=true)` embeds all assets.

### 6.9 Committed fixtures & goldens

```
parity/mod_fixtures/
  basic/            # item + block, folder mod
  allkinds/         # every parser kind + nested, expected.json
  patch/            # patch fixture + expected before/after dumps
  assets/           # sprites, sprites-override, bundles, dp image, sounds, one map with embedded assets
  deps/{a,b,cycle,soft}/  # dependency states
  error/            # one good + one bad content file
  zip/testmod.zip   # GenericModTest equivalent package
  expected_list.json
```

`mind-headless mods *` dumps are byte-stable (sorted keys, LF, trailing newline) and diffed in CI.
