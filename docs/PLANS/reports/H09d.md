### 1. `DesktopBridge::with_host` / `with_host_mut` (`desktop/mod.rs`)

```rust
pub(super) fn with_host<R>(&self, f: impl FnOnce(&MindSimHost) -> R) -> Option<R> {
    let host = self.host.clone()?;
    let guard = host.bind();
    Some(f(&guard))
}

pub(super) fn with_host_mut<R>(&self, f: impl FnOnce(&mut MindSimHost) -> R) -> Option<R> {
    let mut host = self.host.clone()?;
    let mut guard = host.bind_mut();
    Some(f(&mut guard))
}
```

`&self` is enough for both (the helper clones the `Gd`; `bind_mut` needs the
`Gd` mutable, not the bridge). A body that itself returns `Option` ends with
`.flatten()`; the doc comment states the guard contract (no Godot re-entry; a
nested immutable `bind` is safe, a nested `bind_mut` panics).

**Adoption: 36 of the 47 `self.host.clone()` sites** in `desktop/**`, plus
**10 of 13** `self.bridge.host.clone()` sites in `api_*`/`glue` — 46 of 60
overall. 66 call sites (42 `with_host`, 24 `with_host_mut`); a few replace one
clone that the original held across several bind windows and therefore need
more than one call (`try_drop_items`, the door tap, the pause branch).

Kept local (11 desktop + 3 MindInput-level), with the reason:

| Site | Why the clone stays |
|---|---|
| `desktop/config.rs::config_spec` | 490-line body; the single guard spans the whole spec build (no behavioural win from a closure) |
| `desktop/hotkeys.rs::pick_block` | mutates `self.controller`/`self.last_config` between host reads |
| `desktop/mod.rs::refresh_items` | writes `self.item_ids` inside the guard |
| `desktop/mouse.rs::apply_plan_config` | writes `self.last_config` between two bind windows |
| `desktop/mouse.rs::tile_tapped` (`SwitchBlock` arm) | needs the host `Gd` for `try_get_node_as("/root/MindUi")` (Godot node lookup) |
| `desktop/mouse.rs::right_release` | `HostWorld` borrows the guard, then self mutates, then a second bind window |
| `desktop/placement.rs::update_place_line` | `HostWorld` borrows the guard while `self.controller.state` mutates |
| `desktop/selection.rs::plan_info` (2 call sites) | returns a closure that binds per plan; it needs the `Gd` |
| `desktop/selection.rs::finish_schematic_copy` | self mutation between two bind windows + `adopt_select_plans` |

### 3. `MindInput::rebind_and_save` (`api_keybinds.rs`)

```rust
fn rebind_and_save(&mut self, apply: impl FnOnce(&mut BindingState) -> bool) -> bool {
    let changed = apply(&mut self.bindings);
    if changed { bindings::save(&self.bindings); }
    changed
}
```

Adopted at the 3 sites whose preceding statements are identical —
`rebind`, `rebind_key`, `rebind_axis` (all three are

### 5. Constant dedupe: the two 11 px radii stay distinct

S18 flagged `UNIT_TAP_RADIUS = 11.0` and `PLAYER_SELECT_RANGE = 11.0` as a
possible duplicate. Checked against the Java oracle
(`/home/clintonnguyen/g/code_examples/Mindustry/core/src/mindustry/input/`):

- `PLAYER_SELECT_RANGE` is `InputHandler.playerSelectRange`
  (`InputHandler.java:55`): `final static float playerSelectRange = mobile ? 17f : 11f;`,
  used by `canTapPlayer` ("Used for dropping items", `:2041`).
- `UNIT_TAP_RADIUS` feeds the port's `mind_core::input::select_unit_tap`; upstream
  `selectedCommandUnit` (`InputHandler.java:2174-2180`) searches a 4 px box and
  ranks by `dst - hitSize/2`, and `Build.validPlace` has no 11 px hit radius
  (`Vars.itemTransferRange` is 220f). There is no single upstream 11 here.

They are **not** the same constant. Merging them would tie the drop-item radius
to a port-side value and break the moment the mobile port needs `17f`.
Recorded in both doc comments instead; no code change.

### 6. `fire_hotkey` hoist (package item 3) — deliberately **not** done

23 of the 30 `dispatch_action` arms end with `self.fire_hotkey(name)`, but the
arms run different statements before that point (several `self.emit_action`,
early `return`s and effect pushes), so hoisting would move the probe update
after code that currently runs between the arm and the match end. Left as is,
noted for a later change with a test (Follow-ups).

## Deviations from the plan

1. **`with_host` shape.** The package names
   `fn with_host<R>(&self, f: impl FnOnce(&MindSimHost) -> R) -> Option<R>`; that
   is exactly what landed, plus `with_host_mut` with the same `&self` receiver
   (a `&mut self` receiver is unnecessary — the helper clones the `Gd` — and
   would forbid the read-only closures). `Option`-returning bodies use
   `Option::flatten` rather than a second helper.
2. **47-count.** The package's "47×" matches the `self.host.clone()` count in
   `desktop/**` exactly; 36 were adoptable under the package's own re-entrancy
   rule, 11 keep the clone (table above). The MindInput-level
   `self.bridge.host.clone()` sites (13) were treated the same way: 10 adopted,
   3 kept; the 8 `self.sim_host.clone()` sites are all closures that mutate
   `self.mobile` and were deliberately left alone.
3. **`tile_i16` count.** The package says 20× pairs; at this base there are 16
   pair sites plus the 4-way and 2-way forms, 18 sites / 38 calls in total, all
   converted.
4. **`rebind_and_save`.** 3 of the 6 save sites, per the package's "only where
   the preceding statements are identical" clause; the reset/unbind sites keep
   the direct `bindings::save`.
5. **`sync_input_locks`** is an extra helper (4th duplicate family) not named in
   the package file; same statements, same order.
6. **Radius consts not merged** (see §5 above) — S18 asked a later dedupe to
   confirm they are the same constant; they are not.
7. `desktop/mod.rs`'s `tile_i16` / helper imports are two explicit `use` lines
   (`input/mod.rs` and `desktop/mod.rs`) because the two module roots do not
   glob-import each other.
8. No `#[allow(dead_code)]` was added; `gdutil::coords`' existing
   `#![allow(dead_code)]` stays (that file is outside this package's ownership —
   C01 removes it now that `tile_i16` is used).
