   type_name, size) -> Option<Gd<Control>>` already exists at `factory.rs:512`; Rust has no
   overloading, and the package's own step 4 says "Do not add a helper that already exists under
   another name". The `content_texture` + `icon_rect` pair *is* byte-identical in
   `batch_c.rs:299/309` and `batch_campaign2.rs:405`, so a differently named `fitted_icon` in a
   later package is the safe route. Catalogue rows 11 and 15.
2. **`batch_e.rs`'s refresh trio is not byte-identical to `batch_a.rs`'s.** The plan says
   "same as `batch_e.rs` 75–100", but at this base `batch_e.rs:75` sets
   `REQUEST_META = "mind_batch_e_request"` while `batch_a.rs:67` uses `"mind_dialog_request"`.
   The shared trio uses `batch_a`'s body and the plan's explicitly named key
   (`mind_dialog_request`); W2 must migrate `batch_e`'s key when it adopts the helper, which is a
   behaviour change the plan intends.
3. **The refresh trio is associated functions, not methods** (`pub(crate) fn
   request_refresh(node: &Gd<MindDialog>, …)`, `take_request(dialog: &mut MindDialog)`). This
   preserves the original borrow shape exactly; `take_request` calls
   `gdutil::variant::to_text_stringify`, whose body is byte-identical to `batch_a`'s local
   `variant_text`.
4. **`gdutil/variant.rs` is larger than the suggested name list** (43 helpers). That is "one pub fn
   per distinct coercion semantics" rather than per suggested name; rows that are not Variant/
   VarDictionary coercions stay out (the table's fourth column says why). The two support helpers
   `to_f32_option` and `format_godot_float` are included because copied bodies need them.
5. **No test for `to_gstring`.** `GString` allocation needs the Godot engine, so the test could not
   run in a bare host (the package anticipated this). `tile_i16` is pure Rust and has a unit test.
6. **Measured counts drifted from the package's analysis** (see the Step 4 table): 40 close-button
   sites vs 36, 22/30 factory::table vs raw vs 17/14, 23 MindScroll vs 15.
7. **`Cargo.lock` changed** by one line (`serde` in `mind-gdext`'s dependency list). It is the
   mechanical consequence of the allowed `Cargo.toml` line, so it is committed with that group.
8. No existing function signature, call site, scene, manifest, golden or generated binding changed;
   `mod gdutil;` is the only crate-root edit. The gdutil files carry `#![allow(dead_code)]` after
   their `//!` docs; new items in existing files carry `#[allow(dead_code)]` individually.
