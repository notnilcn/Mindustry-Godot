## Deviations from the plan

1. **Line numbers.** The plan's ranges are at `291e30a8`; every site was re-found by
   function name at `4e33a65a` (post-S01 split). Post-plan commits had already applied
   item 11 (`list_save_slots` uses `save_paths()`), added `launch_dialog_json`'s `sun`
   lookup, and grown the planet-mesh color loops from 2 to 3 — counts below follow the
   code at HEAD, not the plan's table.
2. **Item 4 is a pair of free functions over `&ContentRegistry`, not `&self` methods.**
   Two of the ten sites (`clear_planet_research`) run with an owned registry from
   `self.registry.take()`, so a `MindCampaign` method would see `None` there. Adopted 11
   sites (9 `planet_def` + 2 `planet_id_by_name`); the one remaining site is a test.
3. **Item 1: 15 windows switched, 3 kept** (table above): `with_campaign_mut` fails the
   plan's ordering test, `pump_runtime` and `objective_live_stats_json` are the plan's
   own "runtime-out window" exceptions. With items 2 (3) and 3 (2) that is 20 of 23.
4. **Item 5: 6 sites, not 7.** The three other `sector < 0`-shaped checks are not the
   helper body (see the left-in-place table). `u16::try_from` was not used anywhere.
5. **Item 7's `label` is the whole log prefix** (`"autosave queued"`, `"capture save
   queued"`, `"game-over save queued"`, `"saved on exit"`, `"saved outgoing sector before
   launch"`) so all five log lines stay byte-identical; the helper logs
   `"{label} (`{}`)"`. In `save_outgoing_slot` the `self.host()` lookup now happens
   before the preview write (pure field read); preview → request → flush → log order is
   unchanged.
6. **Item 10 uses `save_paths()` inside `slot_file`.** That is the canonical accessor the
   plan's item 11 points at, and `self.paths` is built from the same
   `ProjectSettings.globalize_path("user://")`; the value is identical. 4 `slot_file` + 3
   `slot_user_path` call sites (the plan counted 6 because `save_slot` uses both forms).
7. **Item 11: nothing to do.** `list_save_slots` already called `save_paths()` at this
   base (a post-`291e30a8` commit did it).
8. **Item 12: 2 of 3 sites.** `clear_played_sector_record` logs a warning on the primary
   delete failure, so it keeps its local copy under RULES §4 (same order, different error
   handling).
9. **Item 14: `fail_map` at 4 sites.** The fifth `@map.invalid` exit (`!loaded`) has no
   warn today and kept its shape. `fail_map_key` is called with `&[]` at the pvp site;
   `bundle.format("map.nospawn.pvp", &[])` is identical to `bundle.get` there because
   that bundle string has no `{n}` placeholder.
10. **Item 15: the objectives site keeps its extra condition at the call site.**
    `localized_marker_text` treats an empty bundle value as missing too, so it uses
    `Some(value) if !value.is_empty()`; the helper itself stays the plain
    "value == key" rule.
11. **Item 16: two helpers, and the pump unlock drain uses only the toast half** (its
    block emit already happens through `unlocked_block` before the loop).
12. **Item 17's `vec3_array(&[[f32; 3]])` signature is literal.** The two `grid.tiles` /
    `grid.corners` sites collect their points into a temporary `Vec<[f32; 3]>`; the five
    `Vec<[f32; 3]>` mesh buffers pass directly. `rgba8` replaced 3 loops (the base's two
    `Color::from_rgba8` sites are now three after the planet-mesh emissive split).
13. **Item 18 (optional `dict.set` shorthand) not adopted** — no behaviour change, 39
    sites of churn; left for C01.

- **Promote in C01:** `with_host_runtime`, `read_live_campaign`,
  `flush_settings`, `sector_arg`, `slot_file`/`slot_user_path` and `queue_slot_save` are
  campaign-local today; if a second gdext module needs the same Godot-side seams, they
  belong in `gdutil`/`campaign/util.rs`. `planet_def`/`planet_id_by_name` are the seam X01
  should delete once H01's `Campaign::sector_by_name`-based rewrite lands.
- **Docs to update in C01:** `client/rust/mind-gdext/AGENTS.md`'s `src/campaign.rs` row
  already mentions the tree (S01 follow-up); the new `runtime.rs` helper hub is worth one
  clause there. No `PORT-STATUS` row changed.
- **Behaviour bugs noticed (NOT fixed):**
  - `campaign/saves.rs:243-262` (`delete_save_slot`): the `save-<stem>-name`/`-autosave`
    keys are removed from the store before `slot.delete`; when the delete fails the
    function returns `false` without flushing, so the next boot re-reads the old keys
    while the UI saw the slot as undeletable.
  - `campaign/sector_launch.rs:627` (`start_sector_with_loadout`): the fresh-launch save
    calls `write_live_slot_preview(std::path::Path::new(&save_name))`, passing the slot
    **stem** where every other call site passes the slot file. It works (the preview name
    is derived from the stem) but it is the only site shaped that way.
  - `campaign/sectors.rs:565-574` (`clear_played_sector_record`): the backup file is
    deleted even when the primary save delete failed, so a failed primary delete leaves
    only the backup gone and the stale save in place.
