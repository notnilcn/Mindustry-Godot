## Deviations from the plan

1. **One `impl` block, not many.** At this base each source file has a single
   `impl<'a> ContentJsonParser<'a>` (json) / `impl DataPatcher` (patch); each destination file
   reopens it, which is the structural `impl` header `move_check.py` normalises away.
2. **Imports.** Every child starts with `use super::*;` (RULES §3.3), which imports the parent's
   imports too; no parent import had to be removed. `json/mod.rs` additionally has `use fields::*;`
   (used by its own `apply_research`, and the only way the children see the `*_FIELDS` consts via
   their `use super::*`), and `patch/block.rs`/`patch/unit.rs` import the one private `load.rs`
   helper they call (`parse_liquid_stacks`, `is_index_map`).
3. **`load.rs` range.** The package's 2510–2730 range starts at `fix_content_arrays`; its doc
   comment begins at 2498, and `ModPatchSet` (2578–2586) sits inside the range, so `load.rs` holds
   the contiguous 2497–2729 free-fn block. `mod.rs` re-exports `load::*` so `patch::ModPatchSet`,
   `patch::fix_content_arrays` and `patch::fix_world_content_arrays` keep resolving.
4. **`unit.rs` stayed one file** (905 lines, inside the 300–1000 target; the package allowed a
   split at 2162 "if you prefer", I kept the table's default).
5. **Test bodies de-indented.** Moving the inline `mod tests { … }` bodies into `tests.rs` removed
   the 4-space module indentation; multi-line `r#"…"#` JSON literals therefore lost 4 leading
   spaces each. JSON is whitespace-insensitive and every parse/assertion is unchanged (the suite
   is green and the inventory byte-identical).
6. **`pub(super)` on every moved private item** (RULES §3.2), which is what caused the 3 rustfmt
   re-wraps above. Methods that were already `pub` (`parse_ability`, `parse_weapon_object`, `warn`,
   `bundle_entries`, …) keep `pub`.
7. **Line counts vs the size target:** `json/tests.rs` (1260) and `patch/tests.rs` (1110) exceed
   1000, which RULES §3 permits for test files.
8. `docs/PLANS/baseline/tests-mind-core.txt` is stale by 2 entries (3260 vs 3262 today,
   `sim::test_support::tests::{live_sim_matches_combat_fixture,runtime_sim_matches_production_fixture}`)
   — they landed on `main` after F0 and are unrelated to S16; before/after inventories for S16 are
   identical.
