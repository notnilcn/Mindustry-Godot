## Deviations from the plan

1. **Pilot was batched.** `git mv` + `campaign_link.rs` with the six accelerator methods
   (6838–6962) was generated first, but the first compile ran over the already-complete tree: the
   CPU queue was shared by five sibling packages and a pilot-only compile would have cost another
   5–10 min wait. The secondary block compiled cleanly in that first full check, so the check the
   pilot exists for still happened before any fix-up was needed.
2. **Checks were batched, not per-destination-file.** Same queue reason: 24 destinations at ~2–5 min
   of queue wait each would have serialised the whole wave behind S05. The tree compiled clean on
   the first full check (only unused-re-export warnings) and green on the second; one fmt pass, one
   clippy pass, one test run and one workspace check were run at the end.
3. **Unused re-exports removed.** The plan's snippet includes `pub use render_light::LightSource;`,
   `pub use player::player_near_drop_zone_predicate;`, `pub use logic::compose_logic_player_view;`,
   `pub(crate) use render_units::{factory_preview, reconstructor_preview};` and
   `pub(crate) use command_panel::command_panel;`. With `sim_host` a private module these were all
   flagged `unused_imports` (and `-D warnings` would fail). RULES §3.4's own test — grep for
   `sim_host::<Item>` path users — finds none outside the module, so they were dropped;
   `tests.rs` imports the four it uses directly (`super::render_units::{factory_preview,
   reconstructor_preview}`, `super::player::player_near_drop_zone_predicate`,
   `super::command_panel::command_panel`, plus `super::bar_rows::BarRow` for the type). `BarRow` was
   likewise removed from the `bar_rows` re-export list for the same reason; the other bar types and
   `building_bar_rows` are used by `bars.rs` and stay. If C01 wants those old paths back they can be
   re-added together with an actual user.
4. **`config.rs` doc-comment fix applied** (the plan's one allowed fix): the 3-line
   `block_items_json` doc that sat above `config_to_json` at 11029–11031 is back above
   `block_items_json`.
5. **Section banners move with the following item.** The `// ---- … ----` banners inside the old impl
   were attached as leading comments to the next moved method (they are comments, so `move_check`
   ignores them; keeping them preserves the file's organisation).
6. **No further splits of `logic.rs`/`world_load.rs`.** The plan's thresholds (≈1100 and >1500 lines)
   are not hit: `logic.rs` 946 lines including its 3 inline tests, `world_load.rs` 927. So no
   `logic_display.rs` and no `sector_load.rs`.
7. **Module declaration order** is alphabetical because `rustfmt` has `reorder_modules = true`; this
   is not an item reorder.
