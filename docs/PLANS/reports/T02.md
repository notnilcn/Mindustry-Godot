## Deviations from the plan

1. **`get_campaign_rules` does not exist.** `campaign_rules.rs` called
   `campaign_json("get_campaign_rules", ...)` but the facade has no such
   `#[func]` (`campaign/rules.rs` only has `get_campaign_rules_json`), so that
   read always fell back to the projection's `rules` section. The no-op dynamic
   call is dropped; the typed `CampaignViews.rules` is the only source
   (identical rendered values).
2. **`loadout.rs`'s `launch_capacity`** was also read from a key
   `CampaignViews` does not serialize, so it was always 0 when the context had
   no capacity. The dead fallback is removed; capacity still comes from the
   context, and the loadout editor's own `capacity` state is unchanged.
3. **ABI shims keep the untyped `#[func]`s working** (the plan explicitly keeps
   them): `MindPlanetView::set_sectors(VarArray)` projects each row into the
   typed `SectorView` fields the overlays read; `MindResearchView::set_tree`/
   `node_at` and `MindResearchItemsDisplay::rebuild` (de)serialize at the
   boundary (both T01 structs derive `Serialize`+`Deserialize`). Two widgets
   outside T02's owned paths keep their dictionary inputs and get small
   adapters in owned code instead: `MindSchematicImage::setup` (`width`/
   `height`/`tiles` via `schematic_image_row`) and `MindRowTreeLayout::
   set_entries` (the four keys it reads, via `sector_entry_row`).
4. **Map-list rows** come from `MindPreview.maps_list()` (untyped, and
   `MindPreview` is outside T02's paths), so `map_list.rs`'s row reads stay; only
   the campaign fallback was converted (`map_entry_row`). Same for the
   `planet_view` topology dictionary (`data`) and its `row_i64_or` reads.
5. **`ui/planet/rows.rs` was left as-is.** H04's follow-up suggested adopting
   the F1 helpers there, but its `variant_string`/`row_bool`/`row_i64` are
   deliberately stricter (string-typed text, bool-only flags) than the F1
   lenient helpers; switching would change behaviour for malformed rows while
   the dicts are still `planet_view`/registry data, not T01 views.
6. **`sector_stats` missing-sector fallback.** The sweep opens the dialog with no
   context; the old empty row still rendered the `Time:`/`Threat:` lines. The
   typed build uses `empty_sector_view` for `None` so the rendered output is
   unchanged.
7. **`planet_sector_action`** (label/icon/mode/disabled) is a private Rust
   struct now instead of a `VarDictionary`; it is widget data, not a read model,
   and the rendered buttons are identical.
8. **Dropped the unreachable empty-sector branch** in
   `planet_build_sector_panel` (its only caller skipped the panel for an empty
   selection).
9. **`planet/launch.rs` converts typed rows back at the facade boundary**:
   `remove_sector_items`/`set_pending_launch`/`start_sector_with_loadout` take
   `{item, amount}` stack dictionaries/JSON, so `planet_stacks_of`/`_array`/
   `_json` stay (same payloads, built from the typed `LaunchPlanView`).
10. **`02-FINDINGS #5` (requested-planet filter) was not fixed** — the plan says
    to fix it only in its own commit/task; behaviour is unchanged.
11. **`research.rs` node lookups go through the cached `ResearchTreeView`**
    (`nodes[index]`, depth-first pre-order) instead of `MindResearchView::
    node_at`, so the widget only serializes for the ABI path.
