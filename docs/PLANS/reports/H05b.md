## Deviations from the plan

1. **Group `mod.rs` lines were edited.** `game/mod.rs` (`pub mod util_b;` → `pub mod util;`) and
   `net/mod.rs` (dropped `pub mod util_h;`/`pub mod util_misc;`), because W2-H05 step 4 explicitly
   permits H05b to add/remove files and `pub mod` lines inside the group it owns. `game/` and
   `net/` are filled only by S07, so no other H05 sub-package shares them. Dispatch chains and
   every other line are untouched. (The task brief said not to edit a group `mod.rs`; the package
   file is the specific exception here. If the orchestrator prefers the leaves kept, the merge can
   be reverted by keeping `util_h`/`util_misc` as `pub use` shims.)
2. **`stored_player_name`/`stored_player_color` were not byte-identical copies**: they differ only
   in the constant name, and `PLAYER_{NAME,COLOR}_SETTING` equals `HOST_{NAME,COLOR}_SETTING`
   (`"name"`/`"color-0"`). The merged copy reads the `PLAYER_*` constants; behaviour is unchanged.
   `HOST_*` stays for `net/host.rs`'s own reads/writes.
3. **`ui_show_info`/`ui_show_confirm`**: `game/util_b.rs` had an explicit `has_method` guard and
   `net/util_h.rs` delegated to `ui_call`, which performs the same guard. The merged copy calls
   `common::facade::ui_call`; the observable behaviour is identical (missing facade/method → no
   call).
4. **`game/util_b.rs` was renamed to `game/util.rs`** to reach the package's "one `util.rs` per
   group" goal; the old path was referenced only from H05b files.
5. **`net/join/mod.rs::clear_table_nodes` was a third copy** of the table clear (S07's follow-up
   mentions it). It is deleted; `join` imports the shared `net::util::clear_table_nodes`.
6. **`factory::scroll()` / `on_pressed` / `on_text_changed` not adopted** — see "Kit adoption".
7. `cargo-check --workspace --all-targets` was run because the task brief requires it; RULES §2
   allows it for a split that moves/deletes items other crates might import.
