## Deviations from the plan

1. **Line numbers are the real `1dfed5ab` section headers, not `291e30a8`'s.**
   Most match, but `edit_menu`/`add_menu`/`io`/`pickers` start one line earlier
   (3684/3865/4323/4533) and `variables` ends at 3683. The `ModsDialog` body has
   no internal section comments, so it was split by topic as the package
   suggests: controller/refresh and its list accessors (`mods_dialog.rs`), list
   pane (`mods_list.rs`), details pane (`mods_detail.rs`), import/update/error
   flows (`mods_import.rs`).
2. **Module docs.** `batch_g`'s whole `//!` doc is preserved once, at the top of
   `mods/mods_dialog.rs` (the group's main controller); `batch_j`'s is preserved
   in `logic/editor/mod.rs`. Each other leaf carries RULES §3.7's one-sentence
   `//!` doc + `Upstream:` line only (the F2 stub wording, unchanged, for the
   five pre-created leaves).
3. **Visibility of single-leaf `batch_g` items.** `color_picker.rs` and
   `mod_browser.rs` internals stay private (nothing outside the leaf uses them)
   except `BROWSER_INSTALL_META` (`pub(super)`); this is narrower than a blanket
   `pub(in crate::ui::dialogs)` and follows "never use a wider scope than
   needed". The `batch_j` side follows the package's explicit "make each moved
   item `pub(super)`" literally.
4. **`pub(super)` dispatch.** The old `pub fn dispatch` became `pub(super)`,
   matching the F2 stub leaves and W1-DIALOGS-COMMON step 3 (only
   `dialogs/mod.rs` calls it).
5. **`use io::save;` glue** in `editor/mod.rs` (see Visibility). It is only a
   `use` line; no item was renamed or moved.
6. `mods/mod.rs` gained `pub mod mods_detail; pub mod mods_import; pub mod
   mods_list;` — the only group-`mod.rs` edit, allowed because S10 is `mods/`'s
   single W1 owner.
