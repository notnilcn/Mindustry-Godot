## Deviations from the plan

- **Destination assignment by `fn` line.** The plan's ranges are `fn`-line based, so five boundary
  tests go to the *next* file even though a doc/`#[test]` line sits one line earlier:
  `reconstructor_needs_items_and_time` → `factories.rs` (904), `live_tick_global_advances` →
  `world_processor_a.rs` (2986), `kind_rotates_matches_java` → `kinds_env.rs` (4821),
  `separator_weighted_results` → `t14_blocks.rs` (5675), `bastion_requires_core_zone` →
  `campaign_accelerator.rs` (5975). No test body was split.
- **Every production fixture became `pub(super)`**, including the 15 that were private (the package
  says "every fixture, all `pub(super)`"; RULES §3.2 would not have required it for children, but it
  matches the package and the existing importers).
- **Three logic helpers used from a sibling child file became `pub(super)` and are imported
  explicitly** (`world_effects::{processor_obj, processor_num}`, `units::entity_pos`); the plan did
  not list them, but they cannot stay private in a child file (RULES §3.3).
- **Two relative paths rewritten** (`include_str!` and `super::runtime::…`, above) — the only
  non-visibility text change in the whole package.
- **`sensors.rs` kept as one file** (see above); the plan allowed either shape.
- **`mod` tables** were put after the imports in both `mod.rs` files (the repo's `content/mod.rs`
  style) and the child files start with `use super::*;`.
- The plan's fixture ranges drift by ≤2 lines at HEAD (`place_query` 4584 vs 4586, `set_block`
  1205 vs 1206, etc.); the fixtures listed are all present and kept.
