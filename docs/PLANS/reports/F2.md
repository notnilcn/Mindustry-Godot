## Deviations from the plan

1. **Step 5's "engine-free dispatch test" assumption is wrong.** 14 of the 59 controllers panic
   inside `dispatch` when no engine is bound (godot-ffi's `main_thread_id` assertion, either in the
   constructor or when the temporary `Box<dyn DialogController>` drops): `database`, `load`, `save`,
   `custom_rules`, `campaign_rules`, `planet`, `research`, `sector_stats`, `launch_loadout`,
   `loadout`, `custom`, `editor_maps`, `map_objectives`, `banned_content`. So a plain
   `dispatch(id).is_some()` loop cannot run under `cargo test`. The test instead wraps each probe in
   `std::panic::catch_unwind` and counts `Ok(true)` **and** `Err(_)` as "this module claims the id":
   a `match` arm body only ever runs for the id it matched, so a panic there is itself proof of the
   claim. That keeps the test engine-free and it does verify all 59 ids (it passes); libtest
   captures the caught panic messages, so the run stays clean. The alternative — the sibling
   `batch_campaign2.rs:7422` style `if !godot::sys::is_godot_initialized() { return; }` guard —
   would have made the test vacuous under the required `--cargo-test` gate, so it was rejected.
   No panic hooks are touched (that would be a process-global side effect on parallel tests).
2. **Port-only `Upstream:` line wording.** The table gives `none (shared helpers of the old
   batch_a)` etc.; the files say `//! Upstream: none (port-only; shared helpers of the old
   batch_a)`, i.e. RULES §3.7's required form with the table's text as the reason. Group `mod.rs`
   files say `//! Upstream: none (group module; see the leaves)` because the table has no group
   rows.
3. **`defer_action`/`ui_call`/`rich` copies.** The eight dialog copies are identical (checked
   mechanically). Two others differ and were left alone per the plan: `fragments/player_list.rs:911`
   spells the alias's types as `std::rc::Rc`/`std::cell::RefCell` (same type, textual only) and
   `ui/editor_views.rs:65` drops the `Variant::nil()` tail (its closure returns `()`). The
   `Deferred`/`install_frame_tick` bodies in `batch_campaign2.rs` and `batch_c.rs` differ **only**
   in the two parameterized strings; their doc comments differ in wording ("the GDScript
   `call_deferred` seams" vs "the deferred seams"), and the copy uses the campaign2 wording — body
   text is otherwise identical.
4. **Base line numbers.** This worktree starts at `c49d4b6b`, not the plans' `291e30a8`, so a few
   plan line numbers are 1-2 off (e.g. the `DeferredAction` alias is `batch_b.rs:58`, not `:59`).
   No item was missing or extra.
5. **Java paths.** All upstream paths in the table exist under
   `/home/clintonnguyen/g/code_examples/Mindustry/core/src/mindustry/`; `ResearchDialog.java:86`
   really is the inline root-select `BaseDialog` and `SchematicsDialog.java:774` really is
   `SchematicInfoDialog`. Nothing had to be corrected.
6. `dialogs/mod.rs`'s group dispatch chain is `if let … { return Some(controller); }` (the existing
   style, so the old lines stay untouched) rather than the `.or_else(…)` style used inside the
   group `mod.rs` files, which is what the package's two templates show.
