Behaviour preserved:

- `exit_code` is a pure predicate → exit-code mapping; no arm other than the returned code changed.
- `time_runs` keeps the timed region identical (the closure body is exactly the old loop body),
  returns the same `Vec<u64>` in run order, and propagates errors with the same `?`/`anyhow`
  conversion. The `samples` vector is still allocated before the first timed iteration. Loops whose
  body had setup inside or around the timed region were deliberately **not** converted:
  `io bench-save` save/load, `mods bench` discover/parse/patch/overlay/save-patches,
  `content bench`, `editor bench`, `bench sim_core` (its `samples` allocation is deliberately
  outside the `alloc_count` baseline), `run_catalog_entries` and `cmd_dump`.
- `editor_world` builds the same five values in the same order (`boot_content`, `WorldGrid::new`,
  ECS world, `NoopWorldHooks`, `NoopRenderHooks`); only declarations with no observable order were
  folded. `maps fix` builds the fixture where its `boot_content` call was, before its scratch dir.
- `report_err` consumes the same `Result<(), E>`, calls `state.warn(&error.to_string())` only on
  `Err`, and returns whether the call succeeded so the existing success message is emitted on the
  same branch (no intervening side effects in any of the 11 arms).
- `mods bench cache` assigns the returned vector to `samples` instead of pushing in a loop; the
  sort/percentile consumers see the same values.

## Deviations from the plan

- **`time_runs` signature.** Every qualifying loop is fallible (`sim.tick()`, `SaveIo::get_meta`,
  `make_planet_generator`, `cache.add`); an `impl FnMut()` cannot use `?` without changing error
  behaviour. The helper keeps the package's name and loop shape but takes
  `impl FnMut() -> anyhow::Result<()>` and returns `anyhow::Result<Vec<u64>>`. Four loops adopted.
- **`exit_code` site count.** Adopted at 39 rather than 29: the other ten have the identical
  single-predicate body (listed above). The one inverted `failed` arm is left local.
- **Editor fixture shape.** Returns a private `EditorWorld` struct rather than a bare tuple so the
  four bodies can destructure it (`WorldEditorGrid` borrows `grid`/`ecs`/`content` while the
  callers still pass `&content` to editor methods). Only four bodies had the identical fixture
  setup; the `editor bench`/`mapview` per-run blocks share one booted registry and stay local.
- **`report_err` returns `bool`.** All 11 sites print a success message on `Ok`, so a helper that
  only logs the error cannot sit inside the `Err` arm alone; returning whether the call succeeded
  keeps the success branch in the same place. Signature is otherwise the package's.
- **`infof` not added.** `console.rs` has 65 `state.info(&format!(…))` sites, not 13; the package
  made it conditional on "reads better". A macro would wrap the same `format!` (no gain) and the
  eleven `report_err` rewrites already remove the arm noise; left for C01.
- **`percentile` (S15's follow-up).** Only `exec/bench.rs` is in H09a's ownership; it is kept and
  `exec/io.rs` already imports it. The other three copies are outside the owned files:
  `input_scenarios.rs:1241`, `mp_scenarios.rs:1267`, `stdb_scenarios.rs:497`. `diff` of the bodies:
  `mp` uses a different nearest-rank formula (`div_ceil`), `input` drops the `debug_assert!` on an
  empty slice, `stdb` is behaviourally identical but adds an explicit empty-slice early return.
  Nothing could be adopted without touching unowned files; recorded for C01/W3.
