## Deviations from the plan

1. **Line ranges drifted by one** in four places; fixed by brace-depth check, recorded per RULES §8:
   `helpers.rs` starts at 368 (not 369 — `java_round`'s doc), `keys.rs` starts at 722 (not 723 —
   `key_down`'s doc), `command_mode.rs` ends at 1730 (not 1729), `config.rs` is 3793–4322 (not
   3795–4323: starts on the `// ---- world queries ----` banner, ends before the impl's closing
   brace). The `hotkeys.rs` and `mouse.rs` starts are item starts as planned.
2. **All `const` items stayed in `desktop/mod.rs`**, including `PLAYER_SELECT_RANGE` and
   `ITEM_DEPOSIT_COOLDOWN_MS`, which the plan's `helpers.rs 369–474` range would have swallowed. The
   plan itself says helpers.rs takes "the free helpers … that are **not** consts", and a `const` in
   the module root needs no re-export for the child files. `mouse_key_name` likewise stayed in
   `mod.rs` (it is inside the plan's `1–148` range).
3. **`desktop/tests.rs` holds the body of the old inline `mod tests`** (dedented) and `mod.rs`
   declares `#[cfg(test)] mod tests;`, so the test paths are unchanged (`input::desktop::tests::*`).
   Dedenting made rustfmt re-join three expressions (the four `only-in-old` reflow rows above).
4. **`gestures_json` is a private free fn in `api_mobile.rs`** (plan range 1958–2132). It is called
   only from `mobile_touch_*`/`mobile_tick` in the same file, so it needs neither `pub(super)` nor a
   cross-file import (an earlier reading of the caller set was wrong; the compiler caught it).
5. **`#[func]`-free helpers inside a func range** (plan: "they go to a plain `impl` in the same
   file") were collected into one `impl MindInput { … }` block at the end of `api_keybinds.rs`,
   `api_state.rs` and `api_selection.rs`; the `#[func]`s keep document order.
6. **The two giant `impl` blocks are not single TSV rows** (`impl DesktopBridge` 619–4322, `impl
   MindInput` 315–2126): they are reopened in each destination file, so each method is its own row.
   `docs/PLANS/moves/S18.tsv` has 323 rows; its only uncovered non-blank BASE lines are headers,
   imports, the two impl headers, the closing braces and three `// ---- … ----` banners.
7. `effect.rs` has no `use super::*;` (the enum needs nothing from the module root), and
   `helpers.rs`/`content.rs` add theirs because they call `use super::*` items. The plan's "each file
   starts with `use super::*`" is implemented for every `input/` file it applies to.
8. **`#[func]` count**: BASE has 72 real `#[func]` attributes (a `grep -c '#\[func\]'` yields 74
   because two comments mention the attribute); all 72 moved, verified by the empty api-surface diff.
9. **The brief's single `move_check.py` invocation names `input/api_desktop.rs`**, which the package
   file does not define (it names `api_core`, `api_keybinds`, `api_state`, `api_selection`,
   `api_building`, `api_mobile`). Following RULES §6 the check was run once per source file with the
   real destination set; a combined run over both old files and every new file reports the same
   numbers (10 `only-in-old`, the reflows tabulated above; 21 `only-in-new`).
10. **Commits are one per source file** (`88ab9ba9` desktop, `6e6ae0ff` input) plus this docs commit,
    not one per destination file: a mid-split tree that lacks some of the new files cannot compile,
    so smaller commits would make every intermediate commit red.
