## Deviations from the plan

1. **The 30% line target is not met (`-2.9%`).** H01/H02 wrote their helpers by copying facade
   bodies; adopting them deletes the copy but the core fn keeps the lines, so the facade shrinks
   by the copy minus the new call/parameter plumbing. The package's own decomposition step adds
   signatures + doc comments, which offsets most of it. Reaching 6200 lines would require moving
   the host-facing flows (not copies) into core, i.e. a new W2-sized package, not this one.
2. **`UnlockOutcome` gained `produced`/`auto`** (`mind-core game/tech_tree.rs`). The facade's
   log line needs the two counts, and `names` mixes produced + auto names. Additive fields with a
   doc comment; the H02 test compares against `UnlockOutcome::default()`, which still holds.
3. **Four API families share one commit** (lookups + sector edits + records + boot/clear). They
   edit the same statements (`get_sector_state`, `persist_sector_record_in`, the launch), so a
   hunk-level split would cut single expressions. Every later family has its own commit.
4. **`select_sector_launch` runs before the corrupt-save discard**, because H02 puts the locked
   check inside it and the facade must reject a locked preset before any side effect. The corrupt
   path can only clear the save, so `discard_corrupt_resume` corrects `has_save`/`resume`/
   `lost_replay` to the no-save branch — exactly what the replaced code recomputed. The
   `no_live_core` host read (pure) moves with it, before the discard.
5. **`clear_being_played` at `reset_to_menu` clears every sector** instead of only the session
   sector. Only the played sector can carry the flag (every launch clears the grid first), so
   the observable state is identical; the widening is the H01 helper's documented semantic.
6. **`sector_key` not adopted** (see the lookups row): `format("", id)` vs `None` differs for an
   unknown planet and `rules.sector.is_some()` gates `is_campaign()`.
7. **`set_launch_destination` keeps its inline save.** Its `record.save_info(settings, &planet_name)`
   passes the **destination** planet's name for the played sector's record — a pre-existing bug
   (Follow-ups). `Campaign::save_sector_info` would resolve the played planet's name and change
   saved keys, so the site is left untouched.
8. **`fill_module` needed no facade site** — the two copies were already inside `mind-core`
   (`play.rs`, `runtime/session.rs`) and H02 replaced them there.
9. **`preset_launch_loadout` keeps the map-header read** (`SaveIo::get_meta` + rules parse) and
   only the on-planet filter is `preset_launch_loadout_filter`, as the H02 report specifies.
