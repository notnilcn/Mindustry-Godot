## Deviations from the plan

1. **Defender/FlyingFollow/Hug have no `ai_arms` file.** The plan lists them among the smallest
   arms, but H01 already moved their bodies to `sim/unit_runtime/ai/{defender,follow,hug}.rs`;
   their dispatch arm is one call, so extracting it again would only add a wrapper. `ai/**` is
   not in this package's ownership, so the calls stay in the chain unchanged.
2. **`unit_update_system` is 306 lines, not <250** — reason above; the package's "leave in the
   loop" list is followed literally.
3. **Parameter-shape adaptations inside moved bodies.** A loop-local `mut runtime: UnitRuntime`
   becomes a `&mut UnitRuntime` parameter, so the bodies need three mechanical adaptations,
   all behaviour-free reborrows/rebindings:
   - `} = &mut runtime;` → `} = &mut *runtime;` — 11 sites in assembler, boost, builder, cargo,
     command (×4), logic, missile, suicide;
   - `&mut runtime,` → `&mut *runtime,` — 2 sites (`ground_flying.rs` calls into
     `update_{flying,ground}_ai`);
   - `&mut core_target_cache,` → `&mut *core_target_cache,` — 1 site (`ground_flying.rs`);
   - `&queries` → `queries` — 8 sites in builder, command (×2), ground_flying (×2), logic,
     missile, suicide; with `queries: &TargetQueries` the old borrow of the loop-local value is
     a `needless_borrow`, which scoped clippy `-D warnings` rejects (commit `6843ddd0`).
   Nothing else in any body changed: no statement was reordered, no local was renamed, and no
   expression was rewritten.
4. **`NoAi` is an empty function.** `NoAI.updateUnit(){}` has no body upstream; `no_ai_arm()`
   carries the doc comment and keeps the chain uniform.
5. **The upstream Java tree is not present in this checkout** (`Mindustry/core/src/...` does not
   exist; `screenshots_for_ai/mindustry_source/` holds only images). The Java citations in the
   arm headers are the ones the port's own comments already carried, not re-verified against
   the `.java` files.
