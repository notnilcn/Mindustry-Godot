## Deviations from the plan

- **Line numbers.** The package's table is at plan base `291e30a8`; this branch is based on
  `1dfed5ab`, where `runtime.rs` is +52 lines (the post-plan `on_captured_sector` hook and its test
  landed on main) and `ui/campaign.rs` is +6. I used the HEAD/base layout and recorded line numbers
  at the **branch point `1dfed5ab`** in `moves/S02.tsv`, the same commit RULES §6 uses for
  `move_check --base`, so every row is reproducible with `git show 1dfed5ab:<path>`.
- **`on_captured_sector`** (added after the plan) is not in the package's item list. It is
  sector-capture bookkeeping, so it went to `runtime/game_state.rs` next to
  `game_state_tick_system`, with its own test in `tests/game_state.rs`; both are in the TSV.
- **Re-exports.** Besides the package's list, `runtime/mod.rs` re-exports `on_captured_sector`
  (mind-gdext `campaign.rs`), `CampaignHookQueues` and `CampaignCoreHooks` — every moved `pub` item
  keeps its old path (§3.4). No `pub(crate)` item moved.
- **Tests kept together** in `runtime/tests/` + topic files (the package allows either that or
  children of the code they test); `tests/mod.rs` declares only the seven `mod` lines, each topic
  file imports `crate::game::runtime::*` + `test_support::*` itself.
- **Visibility (original-scope rule).** `unlock_sort_key`/`event_content` are `pub(super)`
  (`tick.rs` uses them). `RuntimeObjectiveEnv` and its fields are `pub(super)` (the objectives tests
  build one). `TeamAiBuildingRow` and its fields are `pub(super)` (the `estimateStats` test builds
  one); `team_ai::{builder,stats}` are `pub(super) mod`, and the five helpers the topic tests call
  (`run_team_base_builder`, `live_type_count`, `turret_enemy_stats`; plus `core_unit_type`,
  `spawn_random_core_unit`, `run_prebuild_ai_defenders` used from `team_ai/mod.rs`) are
  `pub(in crate::game::runtime)` — the nearest common ancestor of `team_ai` and `runtime::tests`.
  Nothing was widened to `pub(crate)`/`pub`.
- **Part B re-export** is the glob form the package offered (`pub use crate::ui::block_catalog::*;`),
  so the whole old surface resolves without an item list that could drift.
- **`move_check` only-in-old = 7**, all rewrite/rustfmt lines as analysed above (the package's
  success wording allows explained lines).
- I did not touch `ui/campaign.rs` beyond removing the moved block (no reordering, no doc edits).
