## Deviations from the plan

1. **Base line numbers.** The branch starts at `1dfed5ab`, not `291e30a8`, and
   the file is 8,518 lines (not 8,325): four post-plan commits (capture hook,
   sector display names, memoization, docs) added 299/removed 106 lines. All
   ranges were recomputed from `git show 1dfed5ab:…`, not copied.
2. **Items at HEAD that the table does not list** (RULES §8, placed by topic):
   `invalidate_caches` → `lifecycle.rs`, `cached_save_slots` → `saves.rs`,
   `count_unit_rows` → `objectives.rs` (free), and the memo helpers
   `dir_mtime_key` + `DirMemo` + `impl<T> DirMemo<T>` → a **new**
   `campaign/cache.rs`. The memo helpers serve both `schematics.rs` and
   `saves.rs` (scattered users, RULES §3.2), so they get `pub(super)` and
   `campaign.rs` imports `DirMemo` for the struct fields. Their three tests are
   not in the package's test table either; they went to `cache.rs` and
   `objectives.rs`.
3. **Commit/order shape.** The accelerator pilot was committed first
   (a `#[godot_api(secondary)]` block compiled clean on the first attempt —
   the package's stop condition did not trigger), then four file-group
   batches, then a rustfmt-only commit. Tests moved **with** their owning file
   instead of in a later step-3 commit; that keeps every commit compiling and
   lets the root `mod tests` keep its own `require`/`require_ok` copies until
   the last batch. Batches, not single files, are the commit unit because
   `campaign.rs` declares every moved `mod` at once; each commit's message
   lists the files it moves.
4. **Root imports were not moved down.** Every child uses `use super::*;`
   (RULES §3.3 sanctions this form), so the root imports are still used and
   clippy reports no `unused_imports`. The step-4 sweep therefore did not
   change anything.
5. **`pub use events::FiredEvent;` carries `#[allow(unused_imports)]`.** The
   item was `pub` inside the old module, so the old `crate::campaign::FiredEvent`
   path must keep resolving (RULES §3.4), but nothing in the crate names it by
   that path and its re-export alone would warn under `-D warnings`.
   `FiredEvents` is used by the root struct, so it has a plain `pub use`.
6. **`cache.rs` has no `use super::*;`.** It uses nothing from the parent; the
   glob would be an unused import (and therefore a clippy error). Every other
   child starts with it as the package requires.
7. **Two `move_check` `only-in-old` lines.** `pub(super)` on
   `localized_content_field`/`emoji_content_name` pushed their one-line
   signatures past rustfmt's width, so `cargo fmt` re-wrapped them; the code is
   identical (move_check prints the wrapped fragments under `only-in-new`).
8. **Allowed doc fixes not applied.** The package allows (does not require)
   the stale `start_sector` doc, the two conflicting paragraphs at the old
   3526–3531 and the duplicated `parse_launch_payload` doc. They were left
   verbatim so the move stays a pure move; they remain for C01 or a W2 pass.
   At HEAD the 3526–3531 pair is the `research_parent_unlocked` doc and the
   7557–7561 duplicate no longer reads as a duplicate, so only the
   `start_sector` sentence is clearly stale.
