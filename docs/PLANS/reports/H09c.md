### 1. Blocks registry — `content/registries/blocks/{def,loader}.rs`

`def.rs` gains one helper next to `resolve_*`:

```rust
pub(super) fn need<T>(value: Option<T>, name: &str) -> Result<T, ContentError> {
    value.ok_or_else(|| ContentError::UnknownName(name.to_owned()))

```

It replaces the 18 `.ok_or_else(|| ContentError::UnknownName(x.to_owned()))?` sites in
`BlockDef::from_spec`/`resolve_item`/`resolve_consume` and the decoration-floor lookup in
`loader.rs::RegistrySink::push` (19 total). `Blocks::id` keeps its direct `ok_or_else` because it
returns the `Result` instead of `?`-propagating. The 99 `spec.X.unwrap_or(…)` field defaults were
left untouched as the package says.

### 2. Turrets — `world/blocks/defense/turrets/{types,ammo,update,config,{find_target_,}tests}.rs`

- `types.rs`: `turret(world, e) -> Option<&TurretState>` and a `_mut` variant
  (`Mut::into_inner`, so the change-detection tick is still written). They replace exactly the 36
  `world.get::<TurretState>`/`get_mut` accesses: 8 in `ammo.rs`, 1 in `update.rs` (loop variable
  renamed `turret` → `e` so the free function is not shadowed) and the 27 test sites, which import
  them as `state_of`/`state_of_mut` because their entity locals are named `turret`. The 6
  `take::<TurretState>` windows (ammo/update/find_target_tests) stay: taking the component out is
  the production borrow shape and the plan's `_mut` helper cannot replace it.
- `config.rs`: `ammo_meta(def) -> (ammoMultiplier, rangeChange, minRangeChange)` replaces the
  repeated `def.map(|d| d.X).unwrap_or(…)` triple in `config_for_inner`'s `item_ammo`/`liquid_ammo`
  closures and in the `test-power` config. The item multiplier keeps the same `as i32` cast and
  `.max(1)` clamp; the liquid one the same `.max(0.001)`. A missing bullet def still yields
  `(1, 0, 0)`.

## Deviations from the plan

- **`need` count.** The package says 26×; the S17-created files contain 20
  `ok_or_else(|| ContentError::UnknownName(…))` sites at this base (18 in `def.rs`, 2 in
  `loader.rs`). 19 are `?`-propagating and were converted; the 20th is `Blocks::id`'s direct
  `Result` return and keeps its local `ok_or_else` so the public accessor stays self-documenting.
- **Turret `_mut` variant is `#[cfg(test)]`.** Every production mutation site (`handle_item`,
  `handle_payload`, `add_build_plan`, `update_turrets`) must `take` the component for the
  `update_turret` call and re-insert it, so the mutable accessor is only used by the 11 test
  `get_mut` sites; a non-test build would flag it `dead_code`. `Mut::into_inner` keeps the
  change-detection tick the old guard wrote. `behavior.rs`/`advanced.rs` were not touched (S17 did
  not create them, and the package says not to touch files S17 did not create).
- **`save`/`load` split instead of one `save_then_load`.** The package names one
  `save_then_load(sim, path)` helper for the 19 save and 16 load pairs, but every test asserts or
  mutates between the two boundaries (decode the bytes, wipe the grid, install the session), so a
  combined helper alone could not serve them. The two drivers are `save`/`load`; the
  plan-named `save_then_load` exists and serves the five round trips that need no intermediate
  step.
- **`io_sim` variants are named and size-parameterized.** The package says several variants differ
  and asks for a name each: `io_sim` (canonical 64×64), `io_sim_sized(32|48)`,
  `io_sim_blocks(16)`, `io_sim_tiles(8|4)`. The three 64×64 setups that do **not** register an
  `IoSimHandler` (`loaded_player_team_units_get_command_ai`, `loaded_logic_unit_keeps_state`, and
  the feature-gated `java_gz_fixture_skips_core_unit`) stay explicit, because adopting `io_sim()`
  would add a handler those tests never had.
- **`TempSave` carries `Deref`/`AsRef`.** The package asks for a `Drop` guard for the 39
  remove calls; the deref impl keeps the existing `&path`/`path.is_file()` uses unchanged rather
  than rewriting 39 call sites.
- **Turret tests import accessor aliases.** `tests.rs`/`find_target_tests.rs` bind
  `turret as state_of` / `turret_mut as state_of_mut`; their entity locals are named `turret`, so
  the canonical helper name would be shadowed at every call site.
