## Deviations from the plan

- **Line ranges.** The plan's numbers are at `291e30a8` and drifted by 1–5 lines at this base
  (`unit_update_system` 2889→2890, systems 3994→3995, `has_core_of_team` 2585→2586, …). I used the
  actual HEAD ranges; every item named by the plan is in the file the plan assigns it to.
  `deaths.rs`'s `impl Sim` segment starts at 701 (the `resolve_deaths` doc), not 702.
- **`building_explosion_terms` re-export is `#[cfg(test)]`.** Its only old-path user is
  `sim::combat_tests` (`#[cfg(test)]`); an ungated `pub(crate) use` is reported
  `unused_imports` in the lib build and fails `clippy -D warnings`. RULES §3.3 explicitly allows
  marking a test-only import `#[cfg(test)]`. A future non-test user must drop the attribute.
- **Test-module bodies.** `tests.rs`/`msav_tests.rs`/`markers_region_tests.rs`/`unit_payload_tests.rs`
  contain the old module bodies dedented by 4 spaces (the `mod x { }` wrapper moved to the `mod x;`
  declaration, with the original cfg attributes). `unit_payload_tests`' old module doc comment
  (9194–9196) became the file's `//!` doc. `rustfmt` then reflowed the dedented bodies — the
  `move_check` explanation above.
- **`impl Sim` blocks.** The one 1,885-line block was reopened in `deaths.rs`, `install.rs`,
  `combat_glue.rs`, `player.rs` and `debug.rs`; the two small blocks at old 4420 and 4587 moved
  whole. Method bodies are untouched.
- **Imports.** `mod.rs` keeps the original import block; every child starts with `use super::*;`
  plus explicit sibling imports (RULES §3.3). While `unit_update_system` was still resident,
  `mod.rs` carried temporary `use`s for the helpers the split had already moved; the final state
  has none. `ai/*` reaches `unit_runtime`'s names through `use super::*` (verified with rustc that
  a two-level glob does not warn the parent import unused).
- **`move_check` interpretation.** `only-in-new` lines are the joined counterparts of the
  `only-in-old` lines (formatting only); no structural additions beyond the file headers, `mod`
  declarations and the re-export block.
- **Doc-comment oddity kept verbatim** (RULES §3.8, not listed by the package): the stale
  `EntitySet::UpdateUnits` doc prefix that sat above `has_core_of_team` moved with it (now
  `deaths.rs:721–725`), so `unit_update_system` still has no doc comment; similarly the
  `UnitRuntime` doc block still ends with `WreckDecalInput`'s sentence (`mod.rs:146–152`).
