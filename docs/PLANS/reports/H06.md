## Deviations from the plan

1. **Part 1 row 10 (`building_center` reuse) is not identical.** `building_center`
   adds the multiblock-centre term (`(x + (size - 1) / 2) as f32 * 8.0 +
   def.offset`) and hardcodes `8.0`; the plan's target expression is the plain
   `x as f32 * TILESIZE_F + def.offset`, which is what the four
   `overlay.rs`/`world_query.rs` sites compute (they already pass the centre
   tile). RULES §4 allows a *differently named* helper, so `tile_center` was
   added in `mod.rs` and adopted at the 3 exact sites; the remaining
   `x as f32 * TILESIZE_F` sites are floor lights with no `Block.offset` term
   (`+ 0.0` would change the sign of zero) and stay inline.
2. **Part 1 row 9 (`mark_world_changed`) is adopted at 8 sites, not 9.** The
   helper sets `world_dirty` first because `emit_world_changed` only signals
   while that flag is set, so it may only replace sites where the flag is
   already guaranteed true. `commands.rs::place_block_rot`,
   `MindSimHost::process` and `MindSimHost::step` call
   `emit_state(); emit_world_changed();` without setting the flag, so replacing
   them would start emitting `world_changed` there — a behaviour change. They
   keep the two statements.
3. **Part 1 row 7: no `dset` helper.** godot 0.5.5's
   `Dictionary::set` takes `impl AsArg<GString>` and `&str` implements
   `AsArg<GString>` (`godot-core-0.5.5/src/meta/args/as_arg.rs`, "String
   arguments"), so the plan's "try that first" applies: the 70 sites use
   `dict.set("key", v)` directly.
4. **Part 2 has 11 accessors, not 6.** `i64` ("player", "target_unit", "unit"),
   `bool` ("bool"), `bool_or` ("queue", "enabled", "direction") and `rotation`
   (the `clamp(0, 3) as i8` chain) are duplicated chains too; each one's body is
   the exact chain it replaces.
5. **`campaign_runtime_mut` returns bevy's `Mut<'_, CampaignRuntime>`**, not
   `&mut CampaignRuntime`: `World::get_resource_mut` returns the
   change-detection guard, and all four call sites bound it as `mut runtime`.
6. **`bar_extras` derives `liquids` itself.** The builder's `liquids` copy is
   already passed to `building_bar_rows`, and the extra `LiquidModule` read
   inside `bar_extras` keeps the helper at six explicit parameters (clippy
   `too_many_arguments` at 7 + `self`). It is the same read, so the values are
   identical.
7. **Part 3.3 keeps more inline than the plan lists.** `mech/treads/crawl/
   payload/legs/weapons/item+mine/statuses/floor` are extracted as planned; the
   scalar reads (`pos`, `core`, `team`, `healthf`, `id`, `is_player`, `health`,
   `fin`) stay in the closure (the plan did not list them, and `fin` has no
   per-family knobs).
8. **Checks were batched per part, not per commit.** The resource queue was shared by
   nine packages; `--cargo-check -p mind-gdext` ran after the Part 1+2 tree, after
   each Part 3 file group and once more for the clippy fix-up (~8 runs). The
   commit order is the package's order, and each commit compiles.
9. **One extra commit** (`8307f585`) fixes two `clippy::all` findings the
   extraction introduced: an `empty_line_after_doc_comments` in
   `push_wall_crafter_rows`, and four `question_mark` sites where the `else` was
   exactly `return None;` in an `Option`-returning fn (now `?`, identical
   behaviour). The plan's "keep each site's `else` body" cannot hold under
   `-D warnings` there.
10. **The pre-edit test-inventory capture failed.** The `--list` job queued
    before the first edit but compiled after it, so it aborted on the
    half-edited tree. The inventory was captured after Part 1/2 (436) and again
    at the end (436); the committed `docs/PLANS/baseline/tests-mind-gdext.txt`
    has 434, and its 208-line delta is the W1 module-path renames
